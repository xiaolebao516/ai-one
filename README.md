# ai-one：多 AI 协作桌面工具

ai-one 是一个 Windows 桌面应用，复用你已经登录的 AI 网页订阅（ChatGPT、Claude、Gemini、Grok），把日常最常用的几件事放在一个窗口里。打开就是四个标签页：

| 标签 | 能做什么 |
|---|---|
| **聊天与讨论** | 一句话同时问多个 AI、并排看回答；或选一个预设模式，让几个 AI 互相讨论、交叉审查，最后出结论。 |
| **派活** | 让一个网页 Chat（ChatGPT）当协调者，ai-one 把它的指令转发给其他已登录的 Chat，并把完整回复送回去。 |
| **任务** | 看 GitHub 仓库里各任务在做什么、哪些等你验收；在任意一行点「派工」，把任务交给 Claude Code、Codex、WorkBuddy 或 Antigravity。 |
| **额度** | 看各 AI 的登录状态和额度；可启动额度 HUD 小窗。读不到的额度如实显示“未知”。 |

聊天页一直保留：切到别的标签再回来，正在进行的对话还在。快捷键 `Ctrl+1…4` 切标签，`Ctrl+K` 打开命令面板。

协作规则见 [`AGENTS.md`](AGENTS.md)。应用基于 [Multi-AI Chat Desktop](https://github.com/TED-H-com/multi-ai-chat-desktop) `v1.9.7`，来源与许可见 [`NOTICE.md`](NOTICE.md)。

## Quick Start（Windows 10/11）

这是源码开发版。首次启动前，请先安装本机开发环境；克隆仓库不会自动安装系统工具。

1. 安装 [Node.js](https://nodejs.org/en/download)（版本要求见下表）、[Rust](https://rustup.rs/) stable 工具链，以及 [Visual Studio Build Tools](https://visualstudio.microsoft.com/visual-cpp-build-tools/)。在安装器中选择 **Desktop development with C++**，并确认包含 MSVC x64/x86 build tools 和 Windows 10/11 SDK。
2. 确认 WebView2 Runtime 可用。Windows 10 1803 及更新版本、Windows 11 通常已包含；如果系统缺失，请从 [Microsoft 官方页面](https://developer.microsoft.com/microsoft-edge/webview2/)安装 Evergreen Runtime。
3. 让 `pnpm` 命令能在 PATH 上运行。Tauri 的 `beforeDevCommand` 会直接调用 `pnpm`，仅执行 `corepack pnpm --version` 成功还不够。在 PowerShell 执行：

   ```powershell
   corepack enable
   ```

   如果提示找不到 `corepack`（Node.js 25+ 不再随 Node 分发 Corepack），请按 [Corepack 官方文档](https://github.com/nodejs/corepack)单独安装 Corepack。然后关闭并重新打开 PowerShell，再运行 `pnpm --version`。如果 `corepack enable` 因安装目录权限失败，可把 shim 安装到用户目录：

   ```powershell
   corepack enable --install-directory "$env:USERPROFILE\.local\bin" pnpm
   ```

   然后把 `$env:USERPROFILE\.local\bin` 加入用户 PATH，并重新打开 PowerShell。环境诊断会在启动前检查这项要求。
4. 克隆并检查环境，再启动应用：

   ```powershell
   git clone https://github.com/xiaolebao516/ai-one.git
   cd ai-one
   node scripts/agent/doctor.mjs
   node scripts/agent/launch.mjs --wait --timeout-ms 600000
   ```

如果 doctor 报告 `MISSING`，先按对应提示处理，再重新运行 doctor。首次 Rust 编译可能需要几分钟。启动脚本只安装项目锁文件指定的依赖，不会自动安装系统工具或修改 PATH。

|---|---|---|

Node 版本要求与 `package.json` 的 `engines` 一致：`Node.js ^22.13.0 || >=24.0.0`。其余 Tauri 前置条件见 [Tauri 官方文档](https://v2.tauri.app/start/prerequisites/)。

## 安装与验证

1. 让 `pnpm` 命令可用。`pnpm tauri dev` 的预启动步骤会直接调用 `pnpm`，所以它必须在 PATH 上：

   ```bash
   corepack enable
   ```

   如果默认安装目录不可写，可以把 shim 安装到用户目录，再把该目录加入用户 PATH（PowerShell）：

   ```powershell
   corepack enable --install-directory "$env:USERPROFILE\.local\bin" pnpm
   ```

   把该目录加入用户 PATH 后，重新打开 PowerShell。

2. 安装依赖（必须使用锁文件）：

   ```bash
   pnpm install --frozen-lockfile
   ```

3. 运行全部前端检查：构建注入脚本、类型检查、lint、单元测试、开发脚本测试和 adapter 校验。

   ```bash
   pnpm verify
   ```

4. 前端生产构建：

   ```bash
   pnpm build
   ```

5. Rust 单元测试与 Clippy（需要先完成第 3 步，它会生成 Rust 编译所需的注入脚本）：

   ```bash
   cargo test --manifest-path src-tauri/Cargo.toml --lib
   ```

   ```bash
   cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
   ```

   rustup 默认配置已包含 Clippy；如果安装时选了 minimal 配置，先运行 `rustup component add clippy`。

   首次构建后，`src-tauri/Cargo.toml` 和 `src-tauri/permissions/autogenerated/` 下的文件可能只因换行符变化显示为已修改（上游在 Windows 上同样如此），不要提交这些变化。

## 启动开发版

```bash
pnpm tauri dev
```

首次运行要编译 Rust 依赖，需要几分钟。应用窗口出现后，在各 AI 的网页窗格里自己登录；应用不会要求或保存密码。

### 由 Codex / Claude Code 从源码启动

仓库保留了上游的源码启动 Skill（Codex：`.agents/skills/launch-multi-ai-chat/`；Claude Code：`.claude/skills/launch-multi-ai-chat/`）和对应脚本。版本化契约见 [`agent-release.json`](agent-release.json) 与 [`docs/AGENT-READY-SOURCE-RELEASE.md`](docs/AGENT-READY-SOURCE-RELEASE.md)。脚本只安装锁定的项目依赖并启动 `tauri dev`，不安装或修改系统工具链。

```bash
node scripts/agent/doctor.mjs --json
```

```bash
node scripts/agent/launch.mjs --wait --timeout-ms 600000 --json
```

```bash
node scripts/agent/stop.mjs --json
```

首次 Rust 编译较慢时，可把 `--timeout-ms` 调大。只有本次运行中、已核实身份的 `[MAC_AGENT] READY control-pane` 标记表示应用已就绪。本项目需要本机图形会话、原生 WebView 和本地网页登录配置，因此不提供 Docker 运行方式。

## 使用前须知

- **本地数据与上游共用**：应用标识仍是上游的 `com.tedh.multiaichat`。网页登录配置、设置和快照保存在 `%APPDATA%\com.tedh.multiaichat` 等目录，与本机安装的上游版本共用。
- **adapter 在线更新来自上游**：应用启动时和每 6 小时会从上游仓库 `main` 拉取各 AI 网页的选择器更新（`src-tauri/src/adapters.rs`），这些更新没有经过 ai-one 验证。
- **指向上游的入口**：“报告 adapter 问题”会打开上游仓库的 Issue 页面；“检查更新”查看的是上游的发布。
- **测试不等于真机验收**：本地测试通过不能证明网页登录、工具调用或完整回复转发在真实账号下可用。真机结论只来自实际运行记录（见 AGENTS.md）。
