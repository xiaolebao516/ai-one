## 0. 一页结论

1. **主线是已经在用的那条链路：CC 协调 → Prodex → GPT 执行 / 独立审计 → CC 本机验证与复派 → 你验收。** 这条链路在工作台外已真实跑通（#26 / #27 / PR #28）。v2 的首要价值是把它**集中到一个好用、看得见进度的入口**，而不是先造一个新的调度器。
2. **一个输入框，四种用法。** 总览最上方一个输入框，四个选项：`聊天`、`想需求`（或其他阶段）、`交给 CC`、`流程`。输入 `/` 可以直接选阶段。选了仓库时默认“交给 CC”。
3. **只有一种“任务”对象。** 临时讨论、单个阶段、预设流程、CC 动态协调的开发，都是同一种任务，只是阶段数量和推进方式不同。讨论就是“没有仓库、只有一个阶段”的任务。
4. **阶段是完整的工作阶段，不是一次模型调用。** 阶段 = 一组参与者 + 一种协作方式（单人 / 讨论 / 主写 + 审计 / 并行执行）+ 结束条件。流程 = 阶段的有序列表。三种推进方式（单个阶段、流程、交给 CC）都由 CC 经 Prodex 派工。角色与模型的对应关系都是可改的默认值。
5. **任务现场按“人话 → 结果 → 原始”三层展开。** 第一眼是“现在”一句话，然后是“需要你”卡片（如果有），再往下是按阶段折叠的进展。派工单、原始回复、Diff、测试放在检查器抽屉里。
6. **“需要你”只有三类：决策、验收、阻塞。** 内嵌卡片，不弹模态框。其他事情（审计 REVISE 后返工、Prodex 超时恢复、会话交接、测试重试）CC 自己处理，记在“已自动处理”里。
7. **证据分开说。** 每条结果都标来源：`已回读`（ai-one 从 GitHub 读到）、`CC 本机运行`、`xx 自述`（不作为证据）、`未运行`。审计结论一定带完整 HEAD，HEAD 变了就重审。
8. **资源和派工通道都看得见。** 每个 AI 的登录、在忙什么、额度（已知 / 网页提示 / 估算 / 未知）一眼可见；Prodex 作为派工通道单独显示状态。
9. **原有的多 AI 聊天保留为独立入口**，随时可以“转为任务”。
10. **网页 AI 担任协调者是远期可选**，原型里列为“交给 GPT 协调（远期 · 未启用）”，不是默认，也不是第一优先实现。

## 2. 核心概念

```
协调者 CC          Claude Code（本机，Opus）。近期唯一实际使用的协调者（#32 第 1 条）
                   规划、选模型、经 Prodex 派工、本机验证、复派返工、必要时亲自做架构 / 前端 / 收尾

派工通道 Prodex     CC 通过它向 ChatGPT 网页发派工首条消息（协作协议 v0.2 模板 B）、取回回复、
                   按 request_id 恢复超时请求。执行会话和审计会话分开

资源 Resource      一个可用的 AI：网页 Chat（GPT、Argon、Opus 网页、Grok）或本地 Agent（Codex 等）
                   状态：登录、在忙什么、排队、额度（四种来源）、你的标注（擅长什么、贵不贵）

阶段 Stage         可复用的工作阶段：想需求 /grill、定方案 /plan、拆任务 /split、执行与审计 /build、总结交付 /ship
                   = 参与者（资源 + 角色 + 模型 + 思考深度）× 协作方式 × 结束条件 × 失败时怎么办

流程 Flow          阶段的有序列表，可保存、复用；将来可以作为另一个流程里的一个阶段

任务 Task          一次具体的工作：目标、可选的仓库 / Issue / PR、阶段进展、事件、需要你的事、规则
                   推进方式三选一：单个阶段 ｜ 流程 ｜ 交给 CC 动态决定
```

**协作方式只有四种**：

| 方式 | 含义 | 例子 |
|---|---|---|
| 单人 | 一个参与者完成 | CC 拆任务 |
| 讨论 | 先独立作答（互相看不到）→ 交换完整回复 → 可选第三方审计 → 最多 N 轮 → 必出汇总 | GPT + Argon 想需求（复用 #18 引擎） |
| 主写 + 审计 | 执行者实现，审计者在**独立会话**审查真实 Diff 与 HEAD；REVISE 就返工，有上限 | GPT 会话 A 写，GPT 会话 B 审，CC 本机验证 |
| 并行执行 | 多个执行者各做一个子任务，作者不审自己 | Codex、CC、GPT 各做一块，交叉审计 |

**不做节点图编辑器**：你描述的组合都是“几个阶段排成一列，每个阶段里几个人怎么配合”。一列卡片就能表达。条件分支用“结束条件”和“失败时”表达，更动态的决定交给 CC。

**角色不写死**：阶段默认团队、CC 能派工的资源、“Opus 网页只做终审”之类的偏好都是可改的默认值。写死的只有安全规则：合并 PR 只能由你确认；作者不能审自己；审计针对当前完整 HEAD；Prodex 结果不明时先恢复，不重复派工或重复写 GitHub。

- **侧栏同时是任务 HUD。** 进行中的任务按仓库分组，前面的形状和颜色就是状态，一键进入现场（场景 D）。
- **不做常驻深色 HUD 栏。** 标题栏中央的状态岛（进行中 / 需要你），和右上角的资源点（CC、GPT、Argon、Opus、Codex 各一个小头像 + 状态点，点开是深色 HUD 浮层，含 Prodex 状态）。#32 第 5 条要求的可观察性由“侧栏 + 状态岛 + HUD 浮层 + 总览”共同承担。
- **总览不是仪表盘。** 只回答：现在怎么样、要不要我、我想做点什么。
- **聊天是平级入口。** 场景 F 要求“足够方便”。

## 4. 关键场景

### A. 临时讨论一个需求（`/grill`）

1. 总览输入框写问题，点“想需求”或输入 `/grill`。底部显示团队（GPT + Argon 讨论 · Opus 审计（可选））和预检结果。
2. 有人没登录时，预检行直接给“打开网页登录”和“本次用 Opus 代替”，不静默换人，也不弹窗。
3. 开始后，阶段条变成讨论环节：独立思考 → 第 1 轮交换 → 审计 → 第 2 轮交换 → 汇总。
4. 主体是**讨论矩阵**：行是环节，列是参与者，每格一句摘要。独立思考时两列同时“思考中，看不到对方”。
5. 结束后出现汇总卡：结论（谁支持、依据类型）、仍有分歧、待补证据、建议下一步。操作：**转入定方案**（CC 建 Task Issue，讨论汇总作为正文）、**继续追问**、**结束并保存**。
6. 卡片写着“‘同意’是 AI 的声明，不等于事实已验证”。

引擎复用 #18。

### B. CC 协调的开发（主线）

1. 选仓库，写需求，“交给 CC”是默认选项。底部显示：CC 协调，经 Prodex 派 GPT 执行或独立审计，需要时请 Argon、Opus。
2. 任务现场的阶段条左侧写“CC 协调 · 经 Prodex 派工”，阶段是 CC 运行中加上去的，最后一格虚线“由 CC 决定”。
3. 进展里的事件按 #26 协议的真实节奏排列：
   - **协调决定**（带理由，旁边有“改派…”）：“方案已定、改动简单：经 Prodex 派 GPT 执行（会话 A）。”附 `Prodex 回执 · request_id 已保存`，可打开**派工单**看实际发出的首条消息。
   - GPT 推送：`提交 a1c93e0 · 已回读`；GPT 说“测试都通过了”标为 `GPT 自述`。
   - **CC 本机运行** `pnpm verify`：`本机运行 · 112/112`。
   - 协调决定：“经 Prodex 开独立会话（会话 B）请 GPT 审计，不带执行上下文。”
   - 审计 **REVISE**，列出问题；自动事件：“CC 把审计意见原文转给执行会话 A，返工第 2 轮（上限 3 轮）。”
   - 新 HEAD → CC 本机验证 → 审计会话**针对新 HEAD** 复审 → PASS。
   - Prodex 请求超时、结果不明：“CC 先用 request_id 恢复，拿到了回复，没有重复派工。”
4. 完成后变成“待你验收”，验收单列出：做了什么、验证（GitHub 回读 / CC 本机运行 / 未运行）、审查（谁、针对哪个 HEAD）、风险，以及“合并 PR”“要求修改…”。合并只能由你确认。
5. 右栏：交付（Issue、分支、PR、CI、审查，均为回读）、团队（CC、GPT 会话 A/B、其他参与者）、**派工通道**（Prodex → ChatGPT 是否可用）、协调简报（你的原话）、规则。

原型里在总览选“交给 CC”点开始，可以从头看完（约 15 秒，开“快进”更快）。

### C. 多模型复杂开发

- “阶段与流程”里选“CC 设计 · 并行开发”：定方案（CC · 设计 · 深度，完成后先给我看）→ 拆任务（CC，每块一个 Task）→ 执行与审计（并行：Codex、CC、GPT 简单项；GPT 独立会话审计；作者不审自己）→ 总结交付（Opus 网页终审、CC 汇总）。
- 点任一参与者改角色、模型、思考深度，并看到它的额度。
- 底部按资源状态提示：“这个流程会用到 Opus 网页 1 次，Opus 接近 5 小时上限……”。
- 流程保存后，在总览选“流程：…”即可；本次的临时调整不改保存的流程。
- 运行中的样子见 `home-lab #7`。

### D. 多仓库任务管理

- 侧栏按仓库列出未完成任务；“任务”页按状态或按仓库分组，可按仓库筛选。每行：状态、标题、仓库与编号、阶段进度条、团队头像、PR、CI、更新时间。
- 总览的“需要你”跨仓库排序：决策 > 阻塞 > 验收。

### E. 人工干预与故障恢复

| 情况 | 出现在哪里 | 你能做什么 |
|---|---|---|
| 某个 AI 登录失效 | 任务内红色卡片；总览“需要你”；资源页；预检行 | 打开网页登录（登录后只补发给它）；本轮由其他 AI 代替；暂停 |
| Prodex 请求超时、结果不明 | CC 先按 request_id 恢复，记入“已自动处理”；恢复不了才变成阻塞 | 任务菜单“恢复派工结果”；不会盲目重发 |
| 额度紧张 | HUD 变黄；CC 改派并说明原因 | 等待恢复；改派 |
| 审计反复 REVISE | 第 3 轮仍不过就停下，决策卡并排展示双方立场 | 采用一方；请 Opus 网页裁决；写下我的决定；不选就一直停着 |
| 需要你决策 / 验收 | 同上 | 内嵌按钮，不弹窗 |
| 我想自己操作 | 团队里点参与者 → 网页或终端视图 → “接管” | 接管时任务暂停；交还时选“采用网页里的最新回复”或“忽略我的操作” |
| 会话太长 | 自动交接，记入“已自动处理” | 任务菜单里也能手动“交接到新会话” |

**暂停**（`Ctrl+.`）：不再发起新的派工或转发，正在生成的回复完整收下。**停止**在“⋯”菜单里。

### F. 自由聊天

- 左侧对话列表；顶部标签：`对比` + 每个 AI 的网页。
- “对比”视图：各 AI 的回答并排成卡片，可展开、转发、引用、在网页中查看。
- 底部：多选目标、预设模式（自由 / 辩论 / 咨询 / 双 AI 讨论 / Coding / 圆桌 / 脑暴）、附件、发送。输入 `/grill` 等命令会带到总览开始对应阶段。
- “转为任务…”把当前问题带到总览。“⋯”里保留回放、导出 .md。

## 5. 任务现场的结构

```
面包屑：仓库 / Issue / PR                                     状态胶囊  暂停  ⋯
阶段条：[CC 协调·经 Prodex 派工] 想需求 ✓ │ 定方案 ✓ │ 拆任务（跳过）│ 执行与审计 ● 第 2/3 轮 │ 总结交付（预计）
────────────────────────────────────────────────────────────────────────────
现在：一句话 + 用时 / 下一步                                         │ 交付：Issue、分支、PR、CI、审查（回读）
需要你：内嵌卡片（只在需要时出现）                                    │ 团队：每人的角色与当前状态
阶段进展：已完成的阶段折叠成一行摘要；当前阶段展开成事件列表          │ 派工通道：Prodex → ChatGPT
          事件类型：协调决定、步骤、结果、审计 REVISE、自动、你        │ 协调简报 / 规则 / 消耗（估算）
底部输入框：对 CC 说话；插话 或 打断并发送
```

| 层 | 内容 | 入口 |
|---|---|---|
| 0 | 状态岛、侧栏圆点 | 永远可见 |
| 1 | “现在”一句话、需要你卡片 | 任务现场顶部 |
| 2 | 阶段摘要、事件、证据标签 | 阶段折叠行 |
| 3 | 讨论各轮、派工单、完整原文、Diff、测试 | 事件旁“展开 / 派工单”→ 检查器抽屉 |
| 4 | 原生网页 / CC 终端 | 团队里点参与者 |

## 6. 状态体系

**任务状态**（颜色 + 形状 + 文字三重表达）

| 状态 | 颜色 | 形状 | 归类 |
|---|---|---|---|
| 进行中 | 蓝 | 脉冲圆点 | 进行中 |
| 返工中 | 紫 | 旋转圆环 | 进行中 |
| 需要你决定 | 琥珀 | 菱形 | 需要你 |
| 待验收 | 琥珀 | 菱形 | 需要你 |
| 阻塞 | 红 | 方块 | 需要你（有可执行操作时） |
| 已暂停 | 灰 | 暂停符 | — |
| 已完成 | 绿 | 对勾 | — |

琥珀色专门表示“和人有关”。

**参与者状态**：就绪、思考中（计时）、等待、排队、需要登录、额度紧张、你在接管、未确认（超过 30 秒没有信号）。

**额度来源**

各工具实际能提供哪种来源都是 [待实测]，原型中的分配只是示例。

## 7. 交互规则

- **不用模态框**处理运行中的事。需要你的事是内嵌卡片；新消息是右下角通知条；Windows 通知只在窗口不在前台且发生“需要你”时发送 [待实测]。
- **一步可达**：开始任务（总览输入框，Ctrl+Enter）；找任务（侧栏 / Ctrl+K）；处理需要你（总览卡片上的按钮）；看某个 AI（右上角 HUD 或任务团队）。
- **快捷键**：Ctrl+K 命令面板；Ctrl+N 新建；Ctrl+. 暂停 / 继续；Ctrl+Enter 开始 / 插话；Esc 关闭浮层；`/` 阶段命令。
- **不替你回答**：决策卡没有默认选项，超时也不会替你选。
- **固定边界**：合并、关闭 Issue 只能由你确认；作者不能审自己；执行和审计用不同会话；审计针对当前完整 HEAD；返工有上限（默认 3）；Prodex 结果不明时先恢复，不重发；同一 Task 只有一个活动写入者。
- **不新增写操作审批层**（沿用 AGENTS.md）：GPT 通过连接器写 GitHub 时，平台自己的授权照常出现，ai-one 不拦截，只回读结果。

**方向**：暖灰纸面 + 墨色，克制、长时间看不累。只有状态有颜色；主按钮是墨色，这样琥珀色的“需要你”永远最显眼。深色元素只有状态岛和 HUD 浮层。完整支持深色主题。

## 10. 模块边界与实现顺序

原则（#32 第 7 条）：**先把已经在用的 CC + Prodex 闭环做得看得见，再逐步把派工接进程序**，不为“GPT 默认调度器”或通用工作流引擎先铺基础设施。

| 步骤 | 模块 | 对应原型 | 说明 |
|---|---|---|---|
| 1 | **外壳与导航**：标题栏、侧栏、视图切换、主题、Ctrl+K；现有聊天搬进“聊天”页，功能不变 | 侧栏、聊天 | 纯前端重排，先保证不丢功能 |
| 2 | **任务 HUD（只读）**：从 GitHub 回读 Issue / PR / 完整 HEAD / CI / 审查评论，按仓库列出任务和“需要你” | 总览、任务列表、交付栏 | 让现在手工跑的 CC + Prodex 闭环在 ai-one 里看得见 |
| 3 | **派工回执**：读取 Prodex 的本机记录（会话、request_id、状态），在任务里显示派工、回复、超时恢复 | 事件里的回执、派工通道 | Prodex 本地记录的读取方式 [待实测] |
| 4 | **讨论阶段 UI**：#18 合并后接到讨论矩阵 + 汇总卡；`/grill` | 场景 A | 依赖 #18 |
| 5 | **资源**：登录状态（已有）+ 额度来源 + 你的标注；HUD 浮层、资源页 | 资源 | 额度识别 [待实测] |
| 6 | **从 ai-one 发起 CC 派工**：在 ai-one 里写需求，交给本机 CC；CC 照现有方式经 Prodex 派工 | 场景 B 的开始 | 程序化入口，不新增调度器 |
| 7 | **主写 + 审计自动循环**：程序识别 REVISE、复派、返工上限、HEAD 绑定的审计 | 场景 B 全流程 | 依赖 2、3、6 |
| 8 | **流程**：阶段库、流程编辑、保存 / 复用 | 场景 C | 依赖 7 |
| 9 | **接管、插话、交接、通知** | 场景 E | — |
| 远期 | Chat → ai-one → 本地 CC/Agent 的反向派工；网页 AI 担任协调者；流程嵌套 | “交给 GPT 协调（远期）” | #32 第 4、7 条 |

建议的代码边界（新增目录，旧代码先不动）：

需要拆成可执行工作时，在 #32 之下建 Task（必要时建更具体的子 Spec），不另建平级的产品方向 Spec。

## 11. 原型说明

- 文件：`docs/design/v2-prototype/`（`index.html`、`styles.css`、`data.js`、`app.js`）。纯静态 HTML/CSS/JS，不是正式 React 组件；全部为**模拟数据**（Issue 号、提交、额度、对话都是虚构的）。

## 12. 主动做的取舍

| 需求里的说法 | 设计里的处理 | 理由 |
|---|---|---|
| Chat 也能作为调度者 | 近期由 CC 协调；网页 AI 当协调者列为远期可选 | #32 第 1、7 条：CC + Prodex 已验证，先把它做好 |
| 完整的工作流编辑器 | 只做竖排阶段卡片，不做节点图 | 组合都能用“阶段列表 + 阶段内协作方式”表达 |
| HUD | 状态岛 + HUD 浮层 + 侧栏任务圆点 + 总览，不做常驻深色栏 | 可观察性不少，但不重复占宽度 |
| 讨论和任务是两种东西 | 合并成一种任务 | 少一套列表和操作；讨论可以“转入定方案” |
| 每次配置参与者 | 默认值 + 本次临时调整 + 保存为流程 | 日常只点“开始” |
| 审计不通过自动返工 | 保留，有上限，超限停下来展示分歧 | 防止无限循环；方向分歧不是代码问题 |
| 显示剩余额度 | 只显示能确认的来源，分四种样式 | 不展示虚假的精确数字 |
