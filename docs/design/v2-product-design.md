## 0. 一页结论

1. **一个输入框，四种用法。** 总览页最上方是一个输入框，下面四个选项：`聊天`、`想需求`（或其他阶段）、`交给 GPT 调度`、`流程`。输入 `/` 可以直接选阶段。日常操作就是“写一句话，选一个用法，点开始”，不需要先配置。
2. **只有一种“任务”对象。** 临时讨论、单个阶段、预设流程、调度者主导的开发，都是同一种任务，只是阶段数量和推进方式不同。讨论就是“没有仓库、只有一个阶段”的任务。这样总览、侧栏、暂停、接管、交接只需要做一套。
3. **阶段是工作单元，不是模型调用。** 阶段 = 一组参与者 + 一种协作方式（单人 / 讨论 / 主写 + 审计 / 并行执行）+ 结束条件。流程 = 阶段的有序列表。调度 = 让一个 AI 动态地挑选和重复阶段。三者共用一个阶段库，角色与模型的对应关系都是可改的默认值，不写死。
4. **任务现场按“人话 → 结果 → 原始”三层展开。** 第一眼是“现在”一句话，然后是“需要你”卡片（如果有），再往下是按阶段折叠的进展。原始回复、转发包、Diff、测试放在右侧检查器抽屉里，按需打开。
5. **“需要你”只有三类：决策、验收、阻塞。** 它们出现在总览最上方、标题栏状态岛和侧栏圆点上，在任务里以内嵌卡片出现，不弹模态框。其他事情（审计不通过、自动返工、会话交接、测试重试）AI 自己处理，记在“已自动处理”里。
6. **资源是一等公民。** 每个 AI 的登录、在忙什么、额度都能一眼看到。额度分四种来源：已知、网页提示、估算、未知，样式不同，不编造精确数字。调度者也读这份信息，所以 Argon 登录失效时，GPT 会改请 Opus 审计并说明原因。
7. **原有的多 AI 聊天保留为独立入口。** 自由聊天、并排对比、切换网页、7 种预设（含开发中的双 AI 讨论）、回放、导出都在“聊天”里。聊天随时可以“转为任务”。
8. **实现标注做进原型。** 原型里每个模块右上角有“已实现 / 部分实现 / 开发中 / 规划”标签，可一键隐藏。以后每实现一块，就把对应标签改掉。

## 2. 核心概念

```
资源 Resource      一个可用的 AI：网页 Chat（GPT、Argon、Opus、Grok…）或本地 Agent（Codex、Claude Code）
                   状态：登录、在忙什么、排队、额度（四种来源）、你的标注（擅长什么、贵不贵）

阶段 Stage         可复用的工作单元：想需求 /grill、定方案 /plan、拆任务 /split、执行与审计 /build、总结交付 /ship
                   = 参与者（资源 + 角色 + 模型 + 思考深度）× 协作方式 × 结束条件 × 失败时怎么办

流程 Flow          阶段的有序列表，可保存、复用；将来可以作为另一个流程里的一个阶段

调度 Conductor     一个资源（默认 GPT）+ 你的调度简报 + 边界规则；它决定调用哪个阶段、委派给谁、何时返工

任务 Task          一次具体的工作：目标、可选的仓库 / Issue / PR、阶段进展、事件、需要你的事、规则
                   推进方式三选一：单个阶段 ｜ 流程 ｜ 调度
```

**协作方式只有四种**，覆盖了你描述的所有组合：

| 方式 | 含义 | 例子 |
|---|---|---|
| 单人 | 一个参与者完成 | Opus 拆任务 |
| 讨论 | 先独立作答（互相看不到）→ 交换完整回复 → 可选第三方审计 → 最多 N 轮 → 必出汇总 | GPT + Argon 想需求（复用 #18 引擎） |
| 主写 + 审计 | 执行者实现，审计者审查真实 Diff；不通过自动返工，有上限 | Codex 写，GPT 审 |
| 并行执行 | 多个执行者各做一个子任务，各自审计 | Codex、Claude Code、GPT 各做一块 |

**为什么不是节点图编辑器**：你要的组合都是“几个阶段排成一列，每个阶段里几个人怎么配合”。一列卡片就能表达，比自由连线的图简单得多，也不会诱导出难以理解的分支。条件分支（例如“审计不通过回到定方案”）由“结束条件”和“失败时”两个字段表达；更复杂的动态分支交给调度者。节点图不在 v2 范围内。

**角色不写死**：阶段的默认团队、调度者能用的资源、“Opus 只用于终审”这类偏好，都是可编辑的默认值。程序里写死的只有两条安全规则：合并 PR 只能由你确认；作者不能审计自己的提交。

```
┌ 标题栏 ─ ai-one │ Ctrl K 搜索/命令 │   ( 2 进行中 · 3 需要你 )  状态岛   │ 资源 HUD 点 │ ─ □ ✕
├ 侧栏 236 ──────────┬ 主区 ─────────────────────────────────────────────────────────────
│ ＋ 新建     Ctrl N │  总览 ：一句话现状 + 万能输入框 + 需要你 + 进行中 + 资源 + 已自动处理
│ 总览           ③   │  任务 ：跨仓库列表，按状态或按仓库分组
│ 任务               │  任务现场：现在 → 需要你 → 阶段进展 │ 右栏：交付、团队、调度简报、规则
│ 聊天               │  聊天 ：对话列表 │ 对比 / 各 AI 网页标签 │ 多选发送 + 预设
│ 阶段与流程         │  阶段与流程：流程库、阶段库、调度设置
│ 资源               │  资源 ：每个 AI 的状态、额度、标注、调度偏好
│ ─ 进行中的任务 ─   │
│ ai-one             │  浮层：检查器抽屉（摘要/讨论/原始记录/代码/测试）、命令面板、HUD、通知条
│  ◌ #42 总览页…     │
│  ◆ #45 会话交接…   │
│ notes-sync …       │
│ ─ 讨论 ─           │
│ 设置 · 主题        │
```

**为什么这样分**

- **侧栏同时是任务 HUD。** 每个进行中的任务一行，按仓库分组，前面的形状和颜色就是状态。不用打开任何页面就知道哪个在跑、哪个卡住、哪个等你，一键进入现场（场景 D）。
- **不做常驻的深色 HUD 栏**（v1 的方案）。它长期占 340px，信息和侧栏、任务右栏重复。改成两处轻量入口：标题栏中央的状态岛（进行中 / 需要你计数），和右上角的资源点（每个 AI 一个小头像 + 状态点，点开是深色 HUD 浮层）。
- **总览不是仪表盘。** 只回答三个问题：现在怎么样（一句话）、要不要我（需要你列表）、我想做点什么（输入框）。没有统计图、没有卡片墙。
- **聊天是平级入口，不藏在任务里。** 场景 F 要求“足够方便”，所以它是侧栏第三项，和任务互不影响。

## 4. 关键场景

### A. 临时讨论一个需求（`/grill`）

1. 总览输入框写问题，点“想需求”或直接输入 `/grill`。底部一行显示团队（GPT + Argon 讨论 · Opus 审计（可选））和预检结果。
2. 某个参与者没登录时，预检行直接给出“打开网页登录”和“本次用 Opus 代替”，不静默换人（#13 原则），也不弹窗。
3. 点开始后进入讨论现场。顶部阶段条变成讨论的环节：独立思考 → 第 1 轮交换 → 审计 → 第 2 轮交换 → 汇总。
4. 主体是**讨论矩阵**：行是环节，列是参与者，每格一句摘要。独立思考时两列同时“思考中，看不到对方”，体现独立取证。点任一格可以展开原文。
5. 结束后出现汇总卡：结论（谁支持、依据类型）、仍有分歧（双方立场并排）、待补证据、建议下一步。三个操作：**转入定方案**（讨论结果作为输入，同一个任务继续）、**继续追问**（底部输入框）、**结束并保存**。
6. 卡片底部写着“‘同意’是 AI 的声明，不等于事实已验证”。

引擎复用 #18：独立初答、只传未送达的新回复、第三方审计、必出报告、失败标记“未完成”。

### B. GPT 调度的快速开发

1. 选仓库，写需求，选“交给 GPT 调度”（选了仓库时这是默认值）。
2. 任务现场的阶段条左侧写“GPT 调度”，阶段是 GPT 运行中逐个加上去的；最后一格是虚线“由 GPT 决定”。
3. 进展里有一种特殊事件：**调度决定**，带理由。例如“改动集中在两个前端组件，属于小改动：自己定方案，不请 Opus。”每条调度决定旁有“改派…”，你可以覆盖它而不必暂停任务。
4. 委派时有“委派单”，可以打开看 GPT 发给 Codex 的具体内容。
5. 审计不通过 → 系统事件“已自动打回返工（第 2 轮，上限 3 轮）”。复审必须针对新 HEAD，不沿用旧结论。
6. 完成后变成“待你验收”，出现验收单：做了什么、验证（每项标来源：GitHub 回读 / CI 内运行 / Agent 自述 / 未运行）、审查（谁、针对哪个 HEAD）、风险，以及“合并 PR”“要求修改…”。
7. 右栏显示调度简报（你的原话）和规则，随时可编辑。

在原型里，总览选“交给 GPT 调度”点开始，可以从头看完这个过程（约 15 秒；打开“快进”更快）。因为 Argon 当时登录失效，GPT 会说明原因并改请 Opus 审计。

### C. 多模型复杂开发

- “阶段与流程”页选一个流程（例如“Opus 设计 · 并行开发”），看到四张阶段卡竖排：定方案（Opus · 设计 · 深度，完成后先给我看）→ 拆任务（GPT）→ 执行与审计（并行：Codex、Claude Code、GPT 简单项；GPT 审计）→ 总结交付（Opus 终审、GPT 汇总）。
- 点任一参与者，弹出小卡片改角色、模型、思考深度，并直接看到它的额度。
- 页面底部会根据资源状态提示：“这个流程会用到 Opus 2 次，Opus 接近 5 小时上限，终审改用 GPT？”
- **不要求每次配置**：流程保存后，在总览选“流程：Opus 设计 · 并行开发”即可；本次的临时调整不改动保存的流程。
- 运行中的样子见 `home-lab #7`：并行子任务各占一行，显示执行者、分支、用时、进度；GPT 自己做的子任务③由 Codex 交叉审计（作者不审自己）。

### D. 多仓库任务管理

- 侧栏按仓库列出所有未完成任务，状态一眼可见。
- “任务”页可按状态（需要你 / 进行中 / 已暂停 / 已完成）或按仓库分组，顶部可按仓库筛选。每行：状态、标题、仓库与编号、阶段进度条（每个阶段一小段）、团队头像、PR、CI、更新时间。
- 总览的“需要你”跨仓库按紧急程度排序：决策 > 阻塞 > 验收。

### E. 人工干预与故障恢复

| 情况 | 出现在哪里 | 你能做什么 |
|---|---|---|
| 某个 AI 登录失效 | 任务里红色内嵌卡片；总览“需要你”；资源页；预检行 | 打开网页登录（登录后只补发给它，不重复发给其他人）；本轮由其他 AI 代替；暂停 |
| 额度接近或用尽 | 资源 HUD 变黄 / 红；调度者自动改派并告诉你（可在资源页改成“先问我”） | 等待恢复；改派；交接给其他调度者 |
| 审计反复不通过 | 第 3 轮仍不通过时停下，琥珀色决策卡并排展示双方立场 | 采用一方；请 Opus 裁决；写下我的决定；什么都不选任务就停着 |
| 需要你决策 / 验收 | 同上 | 内嵌按钮，不弹窗 |
| 我想自己操作 | 任务右栏点参与者 → 网页视图 → “接管” | 接管时任务暂停在当前步骤；交还时选“采用网页里的最新回复”或“忽略我的操作” |
| 会话太长 | 自动交接（可配置），记入“已自动处理” | 任务菜单里也能手动“交接到新会话” |

**暂停**（`Ctrl+.`）：不再发起新的发送或转发，正在生成的回复完整收下。**停止**放在“⋯”菜单里，因为它会中断回复。

### F. 自由聊天

- 左侧对话列表；顶部标签：`对比` + 每个 AI 的网页。
- “对比”视图：问题在上，各 AI 的回答并排成卡片，可展开全文、转发给其他 AI、引用、在网页中查看。没登录的 AI 直接在卡片里给出登录按钮。
- 底部：多选目标、预设模式（自由 / 辩论 / 咨询 / 双 AI 讨论 / Coding / 圆桌 / 脑暴）、附件、发送。输入 `/grill` 等命令会把这段话带到总览，开始对应阶段。
- “转为任务…”：把当前问题带到总览，选一个阶段或流程继续。
- “⋯”里保留回放、导出 .md，以及规划中的会话交接。

## 5. 任务现场的结构

```
面包屑：仓库 / Issue / PR                                     状态胶囊  暂停  ⋯
阶段条：[推进方式] 想需求 ✓ │ 定方案 ✓ │ 拆任务（跳过）│ 执行与审计 ● 第 2/3 轮 │ 总结交付（预计）
────────────────────────────────────────────────────────────────────────────
现在：一句话 + 用时 / 下一步                                         │ 交付：Issue、分支、PR、CI、审查
需要你：内嵌卡片（只在需要时出现）                                    │ 团队：每人的角色与当前状态
阶段进展：已完成的阶段折叠成一行摘要；当前阶段展开成事件列表          │ 调度简报 / 规则
          事件类型：调度决定、步骤、结果、审计未通过、自动、你        │ 消耗（估算）
底部输入框：对调度者 / 当前参与者说话；插话 或 打断并发送
```

**逐层展开**：

| 层 | 内容 | 入口 |
|---|---|---|
| 0 | 状态岛、侧栏圆点 | 永远可见 |
| 1 | “现在”一句话、需要你卡片 | 任务现场顶部 |
| 2 | 阶段摘要、事件、证据小标签 | 阶段折叠行 |
| 3 | 讨论各轮摘要、完整原文、转发包、Diff、测试 | 事件旁“展开”→ 检查器抽屉 |
| 4 | 原生网页 / 终端 | 团队里点参与者 |

**证据标签只有三种说法**：`已回读`（ai-one 自己从 GitHub 读到）、`xx 自述`（AI 说的，未核实）、`未运行`。审计结论一定带 HEAD。

## 6. 状态体系

**任务状态**（颜色 + 形状 + 文字三重表达）

| 状态 | 颜色 | 形状 | 归类 |
|---|---|---|---|
| 进行中 | 蓝 | 脉冲圆点 | 进行中 |
| 返工中 | 紫 | 旋转圆环 | 进行中 |
| 需要你决定 | 琥珀 | 菱形 | 需要你 |
| 待验收 | 琥珀 | 菱形 | 需要你 |
| 阻塞 | 红 | 方块 | 需要你（有可执行操作时） |
| 已暂停 | 灰 | 暂停符 | — |
| 已完成 | 绿 | 对勾 | — |

琥珀色专门表示“和人有关”：需要你、你在接管。其他颜色不用于强调。

**参与者状态**：就绪、思考中（计时）、等待、排队、需要登录、额度紧张、你在接管、未确认（超过 30 秒没有信号，沿用 v1）。

**额度来源**

| 来源 | 样式 | 例子 |
|---|---|---|
| 已知 | 实心进度条 + 百分比 | Codex CLI 报告 5 小时窗口已用 38% |
| 网页提示 | 圆点 + 原文 | Opus 网页出现“接近上限，16:00 重置” |
| 估算 | 斜纹进度条 + “~” | Claude Code 按今日会话估算约 55% |
| 未知 | 虚线空条 | 登录失效、从未读到 |

各工具实际能提供哪种来源都是 [待实测]，原型中的分配只是示例。

## 7. 交互规则

- **不用模态框**处理运行中的事。需要你的事是内嵌卡片；新消息是右下角通知条；Windows 通知只在窗口不在前台且发生“需要你”时发送 [待实测]。
- **一步可达**：开始任务（总览输入框，Ctrl+Enter）；找任务（侧栏 / Ctrl+K）；处理需要你（总览卡片上的按钮直接操作）；看某个 AI（右上角 HUD 或任务团队）。
- **快捷键**：Ctrl+K 命令面板；Ctrl+N 新建；Ctrl+. 暂停 / 继续；Ctrl+Enter 开始 / 插话；Esc 关闭浮层；`/` 阶段命令。
- **不替你回答**：AI 不能替你选择决策卡上的选项；超时只会一直等，不会默认选一个。
- **边界固定**：合并、关闭 Issue 只能由你确认；作者不能审自己；返工有上限（默认 3）；调度者看不到的事实（真实 CI、真实 HEAD）以 ai-one 回读为准。
- **不新增写操作审批层**（沿用 AGENTS.md）：GPT 通过连接器写 GitHub 时，平台自己的授权照常出现，ai-one 不拦截，只回读结果。

## 12. 主动做的取舍

| 需求里的说法 | 设计里的处理 | 理由 |
|---|---|---|
| 完整的工作流编辑器 | 只做竖排阶段卡片，不做节点图 | 你的组合都能用“阶段列表 + 阶段内协作方式”表达；动态分支交给调度者 |
| HUD | 标题栏状态岛 + 资源 HUD 浮层 + 侧栏任务圆点，不做常驻深色栏 | 减少重复信息，把宽度留给任务现场 |
| 讨论和任务是两种东西 | 合并成一种任务 | 少一套列表、状态和操作；讨论可以无缝“转入定方案” |
| 每次配置参与者 | 默认值 + 本次临时调整 + 保存为流程 | 日常只点“开始” |
| 审计不通过自动返工 | 保留，但有上限，超限停下来问你，并展示分歧 | 防止无限循环和浪费额度；方向分歧不是代码问题 |
| 调度者全权推进 | 推进权给它，但合并、自审、额度边界固定 | 符合 AGENTS.md：合并需用户确认、不绕过平台授权 |
| 显示剩余额度 | 只显示能确认的来源，分四种样式 | 不展示虚假的精确数字 |
