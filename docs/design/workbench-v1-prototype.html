主要操作流程

六个高频流程

“停下来问你”只由停止条件触发：双方一致、连续无进展、需要你裁决、网页需要登录或验证、额度用尽。GPT 的 GitHub 写操作不在其中。

开始一个协作任务

  1. Ctrl+N 打开新任务，写目标。
  2. 选模板，默认 执行 + 审计：GPT 执行并负责 GitHub 写操作，Argon 独立审计。
  3. 预检每个网页：已登录、输入框可用。未通过就给出“去登录”，切到该网页完成。
  4. 开始后停在 结果 视图，网页在后台运行。
任务与这组网页会话绑定。切回任务时，网页回到对应会话。

插话

  1. 在底部输入区写指令，选择发给 全部 或某个 AI。
  2. 按 插话：排队，在下一次转发时附带；HUD 待处理里显示“排队”。
  3. 按 打断并发送：先停止正在生成的 AI，再立即发送。
插话记录在原始记录里，结论区只体现它带来的变化。

暂停与继续

  1. 按 暂停 或 Ctrl+.：不再发起新的发送或转发，正在生成的回复完整收下。
  2. 介入横幅变灰：“已暂停 · 不需要你操作”。
  3. 暂停期间可以插话、改停止条件、看原始记录。
  4. 按 继续讨论：从下一步接着跑，附带暂停期间的指令。
“立即停止”放在更多菜单里，会点击网页中的停止按钮，回复记为中断。

裁决分歧

  1. 分歧连续 2 轮没有进展，或 AI 标明需要用户决定时，讨论暂停。
  2. 介入横幅、HUD 待处理、分歧卡同时变为琥珀色。
  3. 选择 采纳 GPT、采纳 Argon、写下我的决定 或 保留分歧。
  4. 决定作为插话发给双方，讨论继续。
也可以“不裁决，继续讨论”，再给它们一轮。

切到网页与接管

  1. 点 ChatGPT 网页 标签只是查看，讨论继续。
  2. 点 接管（或 Ctrl+1 / Ctrl+2）：讨论暂停，标签和 HUD 显示“你在操作”。
  3. 在网页里自由操作，包括处理登录、验证码。
  4. 按 交还协作：采用该 AI 的最新回复作为本轮发言，或忽略这段。
检测到“你在网页里打字”自动暂停，需技术实测后再决定 待实测。

得出结论与会话交接

  1. 满足停止条件时，介入横幅显示结果；窗口不在前台时发 Windows 通知。
  2. 可以 结束任务、再审一轮，或把保留分歧另开任务。
  3. 网页会话过长时，HUD 提示“会话较长”；更多菜单 → 交接到新会话，用模板拼接目标、结论、分歧和最近 2 轮原文。

设计取舍

  • V1 只内置三个模板。原项目的 6 个预设里，Coding 是 8 个固定步骤，Roundtable 是 20 次发言，配置和等待都偏重。
  • 默认分工：GPT 执行并负责 GitHub 写操作，Argon 独立审计。写操作由 GPT 在自己的网页里直接完成，工作台不加确认步骤，只把推送结果写进结论区，交给 Argon 审计。
  • 角色就是一段可编辑的说明（执行、审计、调研员、主持），同一 AI 只能占一个席位。
  • 参与者可以“绑定当前网页会话”，从你已经在聊的那条对话开始，不必新开。
  • “另存为模板”保存参与者、角色和停止条件。阶段的增删和提示词编辑器放到后续版本。
  • 预检沿用原项目的原则：某个 AI 不可用时明确指出并让你处理，不悄悄换成别的 AI。

从 Agent HUD Open 借鉴什么

深色 HUD所有 AI 的运行、讨论、待处理和额度集中在一栏，颜色只表达等级。它的额度阈值是 70% 黄、90% 红，我们沿用这个分级，但只在有页面提示时才着色。
“等待你”排在最前它的面板把等待批准的会话放在第一位，展开一条、其余折叠。我们的 HUD“待处理”同样把最急的一件展开，并配合顶部介入横幅。
一键回到现场它的提醒卡有“回到会话”。我们的待处理条目一键跳到裁决卡或对应网页，不在工作台里复刻网页按钮。
证据会过期它有 unverified 状态：状态太久没有新证据就不再担保。我们的状态超过 30 秒未更新显示“未确认”。
工具类型标签EDIT、BASH、MCP 这类带底色的小标签，对应我们的证据类型：提交、文件、测试、链接。
排版纪律系统字体、等宽数字、白色 8–14% 的发丝线、6–10 的圆角、分段控件。
不照搬刘海与菜单栏位置、Liquid Glass 材质、会动的表情机器人、悬停自动展开。Windows 上改用 Mica 标题栏和固定位置的面板。
Multi-AI Chat Desktop v1.9.6 · 提交 6bcf904

现有界面最值得改造的地方

下图是在隔离目录中用模拟的桌面接口渲染的真实控制面板（四个网页已连接，Claude 思考中，Grok 未登录）。网页本身是原生图层，截图中不会出现。

  1. 同一时间只看到一个网页。中间只有一个舞台，看另一个 AI 要切换，无法同时盯住执行者和审查者。
  2. 配置常驻占位。6 个预设卡片、目标芯片固定在中栏顶部（最高占 42% 高度），运行时也不收起。
  3. 同一状态显示三遍。预设徽标“已就绪 3/4”、目标芯片“就绪 已选”、连接卡“就绪”，却没有“需要你”“用工具”“异议”。
  4. 记录是平铺的气泡。不分轮次、看不到谁转发给了谁、没有分歧与共识，长任务很快变成一面墙。
  5. 运行中只能停止。没有暂停、继续、插话和交还；逐步确认是左栏里的一个文本框。
  6. 会话不等于任务。侧栏只是最近 30 条对话，网页会话不和任务绑定，多个任务容易串线。
  7. 视觉层级弱。默认 Tailwind 方框、处处描边、按钮文字被截断（“开启 Ch…”）。
值得保留
  • 基于证据的连接状态：网页已加载、页面就绪、登录、桥接、适配器分开判断。
  • 预检不悄悄替换 AI；超时给出重试、跳过、取消。
  • 浮层出现时把网页隐藏或冻结的做法（overlay guard），这是我们“控件不盖网页”规则的技术基础。
  • 每个 AI 独立的本地登录配置；诊断报告先预览、不含页面文字。

V1 必须实现与后续优化

V1 必须 核心闭环

  • 结果视图：介入横幅、当前结论、还没解决的分歧、关键证据、讨论进度。
  • 网页切换：结果 ｜ 各 AI 网页，一次显示一个，沿用 Multi-AI Chat；网页在后台运行。
  • 原始记录抽屉：按轮次的完整回复、插话、转发状态，默认收起。
  • HUD 栏与状态岛：运行状态、讨论状态、待处理事项、额度（只显示网页提示）。
  • 任务 = 一组绑定的网页会话；任务栏、Ctrl+K 任务中心；同一时间只运行一个任务。
  • 自由聊天：多选发送，最新回复并列，一键转给另一个 AI。
  • 自动讨论：执行 + 审计（默认）、独立调研 + 交叉质询；可设参与者、角色、最大轮数、停止条件。
  • 控制：暂停、继续讨论、立即停止、插话、打断并发送、接管与交还。
  • 裁决分歧：采纳一方、写下决定、保留；Windows 通知。
  • 手动会话交接（模板拼接）；浅色与深色主题；基础快捷键。

后续优化 V1.x 以后

  • 需要时并排查看两个网页（排查用）。
  • 模板编辑器：增删阶段、编辑提示词、导入导出。
  • 置顶迷你 HUD 与托盘图标，离开窗口也能看到状态。
  • 检测到你在网页中输入时自动暂停 待实测。
  • “用工具”细分状态（浏览、连接器、代码） 待实测。
  • 证据自动校验：提交是否存在、链接是否可达、文件行号是否匹配。
  • 多个任务并行运行（每个 AI 多个网页实例）。
  • 讨论全文搜索、导出 Markdown 报告、回放。
  • 由某个 AI 担任主持人，自动归纳分歧。
  • 不在 V1：Bridge、CLI Agent、远程控制、智能历史压缩。
需要你确认

会影响设计的几个问题

以下按当前默认值设计，答复后再调整。

  1. 主要屏幕尺寸？按 1920×1080、125% 缩放（约 1536×864 可用）设计，最低 1280×720。网页不再并排后，尺寸对布局的影响已经小很多。
  2. 浅色还是深色为默认？当前浅色为主、深色完整支持；HUD 栏和状态岛两种主题都保持深色。
  3. “Gemini Argon”指的是 gemini.google.com 上的某个模型，还是独立入口？这决定预检和登录引导走哪个网址。
  4. 同一时间只运行一个任务是否可以接受？每个 AI 只有一个网页实例时，并行运行会让网页来回切换会话。
  5. 裁决的默认触发是“连续 2 轮无进展”，是否合适？调低会更常打扰你，调高会让讨论更久才停。
