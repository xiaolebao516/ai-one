## 0. 一页摘要

1. **主界面回答三个问题**：讨论得出了什么、还有什么没解决、现在要不要我操作。顶部“介入横幅”直接给出答案（绿：不需要你；琥珀：需要你；灰：已暂停），下面是当前结论、未解决分歧、讨论进度和关键证据。
2. **AI 网页退到后台。** 视图标签“结果 ｜ ChatGPT 网页 ｜ Argon 网页”一次显示一个，沿用 Multi-AI Chat 的单网页舞台。网页在后台继续运行，只在接管、登录或排查时切过去。
3. **原始对话可追溯但不占位。** “原始记录”抽屉按轮次列出完整回复、插话和转发状态，默认收起。
4. **右侧深色 HUD 栏**借鉴 Agent HUD：每个 AI 的运行状态、讨论轮次与双方立场、待处理事项（最急的一件展开）、额度提示。标题栏中央的状态岛是它的压缩版。
5. **分工默认值**：GPT 执行并负责 GitHub 写操作，Argon 独立审计。写操作由 GPT 在网页中直接完成，结果写进结论区交给 Argon 审计，工作台不加确认步骤。
6. **控制保留**：自由聊天 / 自动讨论、暂停、继续讨论、插话、打断并发送、接管与交还、会话交接。
7. **诚实呈现**：“共识”写作“声明同意”；证据只有用户点击核实后才显示“你已核实”；GPT 报告的推送记为“GPT 报告 · 未核实”；额度只显示网页上能看到的提示。
8. **视觉方向**：Claude 的暖白与陶土色 + 苹果式克制精度；HUD 栏和状态岛是仅有的深色元素。

### 1.2 Multi-AI Chat Desktop 的现有结构 [已核实]

- 三栏：左侧会话列表 ｜ 中栏：预设网格 + 目标芯片 + **单个**网页舞台 + 连接卡 ｜ 右栏：对话记录 + 输入框。
- 网页是 Tauri 子 WebView（原生图层），由前端计算位置；`overlayGuard` 在浮层出现时隐藏网页。README 称网页“不在前台时也继续工作”。
- 六个预设：Free、Debate、Consult、Coding（8 个固定步骤）、Roundtable（20 次发言）、Brainstorm（48 次发言）。
- 连接状态由多项证据组合：`webview`、`dom`、`login`（含 blocked）、`thinking`、`bridge`、`adapter`。
- 运行中控制：停止；超时给出重试 / 跳过 / 取消；逐步确认是左栏里的文本框。

## 2. 现有 UI/UX 评估：最值得改造的地方

| # | 问题 | 证据 | 修订版的改造 |
|---|---|---|---|
| 1 | **界面围着过程转，看不到结果** | 中间是网页舞台，右侧是平铺对话；没有结论、分歧、证据的视图 **[已核实]** | 结果视图成为默认主界面 |
| 2 | **配置常驻占位** | 预设网格 + 目标芯片固定在中栏顶部（`max-h-[42vh]`），运行时不收起 **[已核实]** | 配置只在新建任务时出现 |
| 3 | **同一状态显示三遍，关键状态缺失** | 预设徽标、目标芯片、连接卡都显示“就绪”，却没有“需要你”“已暂停”“异议” **[已核实]** | 状态集中到 HUD 栏与状态岛 |
| 4 | **记录是平铺的气泡** | 不分轮次、看不到转发关系 **[已核实]** | 按轮次的原始记录抽屉，默认收起 |
| 5 | **运行中只能停止** | 无暂停 / 继续 / 插话 / 交还 **[已核实]** | 完整的运行控制 |
| 6 | **会话不等于任务** | 侧栏是最近 30 条对话，网页会话不与任务绑定 **[已核实]** | 任务绑定一组网页会话 |
| 7 | **视觉层级弱** | 默认 Tailwind 方框、处处描边、按钮文字截断 **[已核实]** | 新的视觉规范 |

**沿用**：单网页舞台与切换方式（修订版直接采用）；基于证据的连接状态；预检不悄悄替换 AI；超时的重试 / 跳过 / 取消；overlay guard；每个 AI 独立的本地登录配置。

## 3. Agent HUD Open：借鉴与不借鉴

| 借鉴 | 在 Agent HUD 中 | 在本工作台中 |
|---|---|---|
| 深色 HUD | 刘海处的黑色岛与展开面板 | 右侧常驻深色 HUD 栏 + 标题栏状态岛，两种主题都保持深色 |
| 颜色只表达等级 | 额度 <70% 绿、70% 起黄、90% 起红 **[已核实]** | 沿用三级，只在有网页提示时着色 |
| 等待你的排最前 | “Waiting”列表，第一条展开、其余折叠，带计数徽标 | HUD“待处理”：最急的一件展开并带操作；没有时写“现在没有需要你处理的事” |
| 一键回到现场 | 提醒卡上的 “Return to session” | 待处理条目一键跳到裁决卡或对应网页 |
| 不替用户回答 | “never answers for you” | 不复刻、不代点网页里的任何按钮 |
| 状态证据会过期 | `SessionPhase.unverified` **[已核实]** | 超过 30 秒未更新显示“未确认” |
| 小标签 | EDIT / BASH / MCP 带暖色底的小标签 | 待处理类型（裁决 / 汇报 / 接管 / 排队）、证据类型（提交 / 文件 / 测试） |
| 排版纪律 | 系统字体、等宽数字、白色 8–14% 发丝线、圆角 6–10 **[已核实]** | 同样的纪律，换成 Windows 字体 |

**不借鉴**：刘海与菜单栏位置、Liquid Glass 材质、悬停自动展开、会动的表情机器人。

## 4. 设计原则

1. **结果优先。** 打开任务先看到结论、分歧和是否需要介入；过程在需要时才展开。
2. **一眼知道要不要我。** 介入横幅永远在最上方，用颜色、图标和一句话三重表达。
3. **网页是底层，不是舞台。** 不复刻网页的按钮、表单和工具；需要时切过去接管。
4. **可预期。** 进度卡显示离停止条件还有多远；暂停、插话、接管的语义固定。
5. **声明不等于证明。** AI 说“已推送”“已通过”“我们一致”不会被渲染成已验证。
6. **长时间使用优先。** 数字等宽，只有“生成中”持续动画，高频动作有快捷键。

## 5. 信息架构与页面结构

### 5.1 对象模型

```
任务 Task
 ├─ 目标、模板、停止条件、状态（空闲/运行中/暂停中/已暂停/等待你/已完成/出错）
 ├─ 席位 Seat × 2–4
 │   ├─ AI、角色（执行 · GitHub 写操作 / 独立审计 / 调研员 / 主持）
 │   └─ 绑定的网页会话段：第 1 段 URL → 交接后第 2 段 URL …
 ├─ 结果：当前结论（一句话 + 支撑要点）、未解决分歧、关键证据、写操作结果
 ├─ 进度：阶段、轮次、用时、停止条件进度
 ├─ 待处理：裁决、登录 / 验证、额度、接管中、排队的插话
 └─ 原始记录：轮次 → 回复 / 插话 / 转发包 / 系统事件
```

- 一个 AI 在一个任务中只占一个席位。
- 每个 AI 只有一个网页实例时，**同一时间只能运行一个任务**；切换到其他任务会先暂停当前运行。**[推断]**

### 5.2 页面与区域

| 页面 / 区域 | 入口 | 内容 |
|---|---|---|
| **结果视图**（默认） | 视图标签“结果” | 介入横幅、当前结论、还没解决、讨论进度、关键证据、输入区 |
| **网页视图** | 视图标签“ChatGPT 网页”等，或待处理条目 | 一个 AI 的原生网页；查看不影响讨论，接管则暂停讨论 |
| **原始记录抽屉** | 右上角“原始记录” | 按轮次的完整回复、插话、转发状态；在网页中打开 |
| **HUD 栏**（常驻） | 右侧 | 运行、讨论、待处理、额度 |
| 任务中心 | 点任务标题或 Ctrl+K | 搜索；分组：需要你 / 进行中 / 最近 / 已归档 |
| 新建任务 | Ctrl+N | 目标、模板、参与者、停止条件、预检 |
| 证据页 | 关键证据“全部 →” | 全部证据、核实状态、引用位置 |
| 设置 | 任务栏底部 | AI 登录状态、默认角色说明、快捷键、主题、通知 |

### 5.3 窗口尺寸

最小 1280×720，按 1920×1080、125% 缩放（约 1536×864 可用）设计。网页不再并排，宽度压力明显变小：

| 区域 | 尺寸 |
|---|---|
| 标题栏 / 视图标签栏 | 44 / 40 |
| 任务栏 | 60 |
| HUD 栏 | 340（< 1366 宽时可收起为 64 的图标列，只保留状态环与待处理计数） |
| 结果区 | 自适应；左栏（结论、分歧）自适应，右栏（进度、证据）322；< 1100 宽时改为单栏 |
| 网页视图 | 占满结果区；ChatGPT / Gemini 在 ≥ 900px 时为桌面布局 **[待实测]** |

## 6. 主要操作流程

### 6.1 开始一个协作任务
1. Ctrl+N 打开新任务，写目标。
2. 选模板，默认 **执行 + 审计**：GPT 执行并负责 GitHub 写操作，Argon 独立审计。另有“独立调研 + 交叉质询”和“自由聊天”。
3. 预检：已登录、输入框可用。未通过的 AI 给出“去登录”，切到该网页完成，不自动替换。
4. 开始后停在结果视图，网页在后台运行。

### 6.2 插话
- **插话**（Ctrl+Enter）：排队，在下一次转发时附带；HUD 待处理显示“排队”。
- **打断并发送**（Ctrl+Shift+Enter）：先点击目标网页的停止按钮，再立即发送。
- 插话写入原始记录；结论区只体现它带来的变化。

### 6.3 暂停与继续讨论
- **暂停**（Ctrl+.）：不再发起新的发送或转发，正在生成的回复完整收下；横幅变灰：“已暂停 · 不需要你操作”。
- 暂停期间可以插话、改停止条件、看原始记录。
- **继续讨论**：从下一步接着跑，附带暂停期间的指令。
- **立即停止**（更多菜单）：点击网页中的停止按钮，回复记为中断。
- 中途切到“自由聊天”等同于暂停，切回“自动讨论”可继续。

### 6.4 裁决分歧
1. 分歧连续 2 轮没有进展（默认值），或 AI 在协作标记中标明需要用户决定时，讨论暂停。
2. 介入横幅、HUD 待处理、分歧卡同时变为琥珀色；窗口不在前台时发 Windows 通知 **[待实测]**。
3. 选择：采纳 GPT ／ 采纳 Argon ／ 写下我的决定 ／ 保留分歧。输入区也可以直接写决定。
4. 决定作为插话发给双方，讨论继续；也可以“不裁决，继续讨论”，再给一轮。

### 6.5 切到网页与接管
1. 点“ChatGPT 网页”标签只是查看，讨论在后台继续。
2. 点“接管”（或 Ctrl+1 / Ctrl+2）：讨论暂停；标签、状态岛和 HUD 显示“你在操作”。
3. 在网页里自由操作，包括处理登录、验证码。
4. 点“交还协作”：采用该 AI 的最新回复作为本轮发言，或忽略这段操作。

检测“用户在网页中输入”自动暂停 **[待实测]**，验证可靠后再加入。

### 6.6 得出结论与会话交接
- 满足停止条件时，介入横幅显示结果：“讨论结束：得出结论，保留 1 项分歧”。操作：结束任务 ／ 再审一轮 ／ 保留分歧另开任务。
- 网页会话过长时，HUD 提示“会话较长”（阈值 **[待实测]**）；更多菜单 → 交接到新会话：用固定模板拼接任务目标、已声明同意的结论、未决分歧、最近 2 轮原文，可编辑后发送。V1 不做智能压缩。

### 6.7 GitHub 写操作（说明，不是额外流程）
- GPT 在自己的网页中通过连接器直接完成写操作。工作台不弹确认、不拦截。
- 写操作的结果（推送的提交、更新的 PR）由 GPT 在回复与协作标记中报告，显示在当前结论下方：“GitHub 写操作由 GPT 执行：已推送 3f2a1c9 …”，标为“GPT 报告 · 未核实”，并作为证据进入 Argon 的下一轮审计。
- 若网页本身弹出连接器授权或登录，属于“网页需要登录 / 验证”，按 6.5 切过去处理。

### 7.2 介入横幅：现在要不要我

| 状态 | 颜色 / 图标 | 标题 | 操作 |

| 需要你裁决 | 琥珀 ⚠ | 需要你裁决 N 项分歧 | 去裁决 |
| 需要你处理网页 | 琥珀 ⚠ | Argon 网页需要重新登录 / 验证 / 额度已用尽 | 去 Argon 网页 |
| 已暂停 | 灰 ‖ | 已暂停 · 不需要你操作 | 继续讨论 |
| 得出结论 | 绿 ✓ | 讨论结束：得出结论，保留 N 项分歧 | 再审一轮、结束任务 |
| 卡住 / 出错 | 红 ✕ | Argon 连续 10 分钟没有回复 | 重试、跳过本轮、取消 |
| 自由聊天 | 灰 ⇄ | 自由聊天 · 不会自动讨论 | 转为自动讨论 |

横幅只描述一件事。同时有多件时，按“出错 > 需要你 > 结论 > 运行”取最高一件，其余在 HUD 待处理中列出。

### 7.3 当前结论

- 标题行：“当前结论” + 状态（尚未一致 · 第 3 轮 ／ 双方声明同意 · 第 4 轮）+ 更新时间。
- 一句话结论，衬线 21px。
- 支撑要点（3–5 条）：每条右侧显示谁同意（头像）和证据状态（你已核实 ／ 未核实）。
- 写操作结果行：“GitHub 写操作由 GPT 执行：已推送 … 并更新 PR …”，标“GPT 报告 · 未核实”。
- 数据来自协作标记（§7.8）中的“结论”和“主张”字段；某轮没有更新时保留上一版，并显示更新时间。

### 7.4 还没解决

- 计数徽标；按“需要你 > 讨论中 > 等待回应”排序。
- 分歧卡：问题一句话；每个 AI 一行立场 + 证据标签；状态（讨论中 · N 轮 ／ 需要你裁决 ／ 保留 · 另开任务）。
- 需要你裁决时整张卡琥珀色高亮，并给出采纳 GPT、采纳 Argon、写下我的决定、保留分歧。
- 次要问题（例如“等 GPT 回应”）以虚线行显示，不占卡片。

### 7.5 讨论进度与关键证据

- **进度**：阶段竖向列表（独立取证 → 交叉审计 → 修正与复核 → 汇报），当前阶段写正在发生什么（“Argon 审计中 · 01:12”）；下面是停止条件进度：双方一致（未满足 ／ 已满足）、连续无进展（1 / 2 轮）、最多轮数。
- **关键证据**：最重要的 4 条（类型、引用、核实状态），“全部 →”进入证据页。核实状态只有“未核实”和“你已核实”两档；AI 自述（“GPT 称通过”）原样标出。

### 7.6 HUD 栏

| 区块 | 内容 | 规则 |
|---|---|---|
| 运行 | 每个 AI 一行：头像环、名称与角色、运行状态 + 计时 | 状态见 §7.7；超过 30 秒无信号显示“未确认” |
| 讨论 | 第 N / 最多轮、阶段名、轮次进度条、双方立场、结论 / 分歧数 | 立场来自协作标记，缺失时写“未标注” |
| 待处理 | 计数徽标；最急的一件展开（类型标签、标题、等待时长、操作按钮）；其余折叠；排队的插话 | 没有时写“现在没有需要你处理的事” |
| 额度 | 每个 AI：等级点、进度条、文字（未见提示 ／ 接近上限 ／ 已达上限，HH:MM 恢复）+ 来源时间 | 只显示网页上出现过的提示，不估算剩余量 **[待实测]** |

头像环的颜色表示额度等级（绿 / 黄 / 红；无信息时为虚线环），与 Agent HUD 的额度环一致。

### 7.7 运行状态

| 运行状态 | 信号来源 | 呈现 | 标注 |
|---|---|---|---|
| 未登录 | 登录检测器 | 琥珀“需要登录”，进入待处理 | [已核实] 上游已有 |
| 就绪 | 页面就绪 + 输入框可用 | 绿“就绪” | [已核实] 上游已有 |
| 排队 | 工作台调度 | 灰“排队” | [推断] |
| 生成中 / 审计中 | 生成指示 / 停止按钮存在 | 蓝色脉冲点 + 计时；按角色写“执行中”“审计中” | [已核实] 上游 `thinking` |
| 完成 | 完整回复已收取 | 绿“完成”或具体结果（“已推送 · 等审计”） | [已核实] 上游已有 |
| 需要你（网页） | 登录页、验证码、限额横幅 | 琥珀，进入待处理与横幅 | [待实测] |
| 卡住 | 超时、页面替换、适配器失效 | 红，附重试 / 跳过 / 取消 | [已核实] 上游已有 |
| 已暂停 | 用户操作或等待裁决 | 灰暂停图标 | [推断] |
| 你在操作 | 用户点击接管 | 陶土色手形图标 | [推断] |
| 未确认 | 超过 30 秒没有状态信号 | 灰，保留上一个状态并加“未确认” | [推断]，借鉴 Agent HUD |

“用工具”（浏览、连接器、代码）只有能可靠识别时才单独显示，否则合并进“执行中”。**[待实测]**

### 7.8 结构化依赖：协作标记 [推断，待实测]

结论、分歧、立场、证据依赖每条回复末尾的一小段结构化标记，由工作台在转发包里要求 AI 以固定格式结尾：

```
<协作标记>
立场：同意 | 异议 | 修正 | 需要信息
结论：一句话（可空）
主张：……
证据：类型 | 引用 | 说明
写操作：提交 / PR / 分支（GPT 执行时填写）
需要用户决定：……（可空）
</协作标记>
```

- 解析失败或缺失时，相关区块显示“未标注”，转发和原始记录不受影响。
- 格式、提取方式、各网页是否会改写标记，需要技术方案确认。

### 7.9 原始记录抽屉

- 从右上角“原始记录”展开，宽 480，覆盖结果区右侧（结果视图中没有原生网页，浮层不受图层限制）。
- 按轮次分组，旧轮次自动收起；每条显示完整回复（可展开全文）、字数、转发状态、“在网页中打开 ↗”。
- 筛选：全部 ／ 各 AI ／ 我的插话 ／ 转发包（查看工作台实际发出的内容，用于排查）。
- 列表虚拟化以支撑长任务。

### 7.10 网页视图

- 视图标签切换，一次一个网页，复用上游的单网页舞台。
- 顶部是席位标题条（AI、角色、状态、会话 URL 与段数）。查看时显示提示“讨论在后台继续，要在网页里操作请先接管”和“接管”按钮；接管后变为陶土色条：“你已接管 ChatGPT，自动讨论已暂停”，并给出两种交还方式。
- 网页上方不覆盖任何控件。

### 7.11 自由聊天

- 输入区目标芯片可多选，消息同时发给选中的 AI。
- 结果区上方并列显示各 AI 的最新回复（摘要 + 展开全文 + “转给对方”），下方保留上一次自动讨论的结论与进度。
- 不显示轮次，不触发停止条件。

### 7.12 快捷键

Ctrl+N 新任务；Ctrl+K 任务中心；Ctrl+. 暂停 / 继续讨论；Ctrl+Enter 插话或发送；Ctrl+Shift+Enter 打断并发送；Ctrl+0 结果视图；Ctrl+1–4 切到对应网页，再按一次接管；Ctrl+L 原始记录；Esc 关闭抽屉或浮层。

## 9. 视觉风格与组件规范

### 9.1 方向
Claude 的暖白纸面与陶土色，加上苹果式的克制：发丝线分区、少阴影、数字等宽、颜色只表达状态。HUD 栏与状态岛是仅有的深色元素。Windows 11 上遵守系统习惯：右上角最小化 / 最大化 / 关闭，支持贴靠布局，标题栏可用 Mica **[待实测]**。

- 界面：Segoe UI Variable Text + Microsoft YaHei UI。

## 10. V1 必须实现 vs 后续优化

### V1 必须
- 结果视图：介入横幅、当前结论、还没解决的分歧、关键证据、讨论进度。
- 网页切换：结果 ｜ 各 AI 网页，一次显示一个；网页在后台运行。
- 原始记录抽屉：按轮次的完整回复、插话、转发状态，默认收起。
- HUD 栏与状态岛：运行状态、讨论状态、待处理事项、额度（只显示网页提示）。
- 任务 = 一组绑定的网页会话；任务栏、任务中心；同一时间只运行一个任务。
- 自由聊天：多选发送，最新回复并列，一键转给另一个 AI。
- 自动讨论：执行 + 审计（默认）、独立调研 + 交叉质询；可设参与者、角色、最大轮数、停止条件。
- 控制：暂停、继续讨论、立即停止、插话、打断并发送、接管与交还。
- 裁决分歧：采纳一方、写下决定、保留；Windows 通知。
- 手动会话交接（模板拼接）；浅色与深色主题；§7.12 快捷键。

### 后续优化
- 需要时并排查看两个网页（排查用）。
- 模板编辑器：增删阶段、编辑提示词、导入导出。
- 置顶迷你 HUD、托盘图标。
- 检测用户在网页中输入时自动暂停。
- “用工具”细分状态。
- 证据自动校验：提交是否存在、链接是否可达、行号是否匹配（可用于核实 GPT 报告的推送）。
- 多任务并行（每个 AI 多个网页实例）。
- 全文搜索、导出 Markdown 报告、回放。
- 指定某个 AI 担任主持人，自动归纳分歧与结论。
- 不属于 V1：Bridge、CLI Agent、远程控制、智能历史压缩。

### 从 V1 移除
- 每次转发前确认；工作台层面的 GitHub 写操作确认。

## 12. 需要你确认的问题

1. **主要屏幕尺寸。** 当前按 1920×1080、125% 缩放设计，最低 1280×720。网页不再并排后，尺寸影响已经小很多。
2. **默认主题。** 当前浅色为主、深色完整支持；HUD 栏与状态岛始终深色。
3. **Gemini Argon 的入口。** 是 gemini.google.com 上的某个模型，还是独立入口？这决定预检和登录引导走哪个网址。
4. **一次只运行一个任务是否可接受。**
5. **裁决的默认触发**是“连续 2 轮无进展”，是否合适？调低会更常打扰你，调高会让讨论更久才停。
6. **品牌标志。** 原型用字母头像，正式版是否使用各家官方标志。
